# Plan: the figure pipeline in the repository

Agreed with the owner on 2026-10-17 (`docs/proposals/figure-animation.md`, open question 3): move the
animation pipeline into the repository as it is, with a generated registry, before more animation work.

## Problem

Everything that turns a Tripo model into an animated figure lives in an untracked folder of one
checkout (output/soldier-animation/): the line infantryman's pipeline (51 clips), the multi-part units'
pipeline (a gun and its crew, a cavalryman on his horse), their outputs and their renders. None of it is
versioned or reviewed, a cleanup would lose it, and nothing in the repository says which figures and
clips exist. Each script treats its own folder as source, work area and output at once.

## Scope

In:
- the scripts to `tools/unitpipe/`: `infantry/` (the infantryman, as built) and `units/` (the multi-part
  units), with one paths module so code, sources, work files and outputs each have their own place;
- the Tripo sources kept out of git, in `assets/tripo/`, listed with their SHA-256 in
  `tools/unitpipe/sources.json`; the scripts read them from there;
- work files (Blender files, frames, logs) and outputs (GLBs, clip tables, videos, preview pages) in
  a git-ignored output/ folder;
- the registry `data/figures/index.json`, generated by `tools/unitpipe/registry.py` from the published clip
  tables: figures (kind, pipeline, sources by name: their hashes are in `tools/unitpipe/sources.json`, one
  home), the published files, clips (frames, fps, loop, events, root speed in m/s, what each leads to); a
  unit test checks it is consistent, with figure kinds read from the ruleset;
- the system doc (the pipeline, its workflow and checks) and the record of the file layout (decision 0038).

Out (later PRs): the generalised bake for crews and horses (the game's bake knows only the infantryman,
on the crowd-bench branch), the infantryman moved onto the new toolkit, the bindings of decision 0037,
committed figure data files, the pistol.

## Approach

1. `tools/unitpipe/paths.py`: the repository root; `assets/tripo/` (sources, overridable by
   `UNITPIPE_ASSETS`); output/unitpipe/<pipeline>/ (work); output/figures/<figure>/ (published). Every script
   takes its paths from there; imports stay relative to the script's folder.
2. Move the two pipelines with the smallest edits: paths only, no change to any pose, clip or check.
   `run-all.sh` of each rebuilds from the sources, checks and publishes. The infantry's one-off steps
   (inspect, components) run in it too, so a fresh checkout rebuilds.
3. `tools/unitpipe/registry.py` reads each published `clips.json` and writes `data/figures/index.json` (sorted, stable);
   `--check` compares with the committed file.
4. `.gitignore`: output/, assets/tripo/ and Python's caches.

## Acceptance

- Both `run-all.sh` pass from a fresh work folder (every check prints its full output and exit code).
- **Nothing changed:** the rebuilt clip tables, validation results and contact tables are byte-identical
  to the ones published from the old folder; the GLBs reimport with every clip.
- `tools/unitpipe/sources.json` hashes match the files in assets/tripo/.
- `npm test` (with the registry test) and `node tools/check-docs.mjs` pass.

## Review rounds

- **Round 1** (`/code-review high`): severe: the units' run-all could pass a failed step (Blender without
  `--python-exit-code 1`, steps judged by grep through a pipe), so a crash published stale files. Fixed: every
  step is judged by its exit code with its full log kept, the shell scripts take their folders from
  `tools/unitpipe/paths.py`, the infantry's comparison fails without its archive (unless skipped on purpose),
  videos are published with their figure, the preview reads only its unit's clip table, a stale texture relink
  and dead code removed, the registry built once and failing clearly when nothing is published, the plan's
  registry contents corrected, the test's figure kinds read from the ruleset.
- **Round 2** (`/code-review high`): moderate only, fixed and stopped: override paths made absolute (a relative
  one moved under the scripts' change of folder); the infantryman's published LOD GLBs reimported with every
  clip (the roundtrip read an intermediate file); the video script judged by Blender's exit code; the source
  list never overwritten by an empty scan; each publish replaces its figure's files; an unused input of the
  cavalry build, a repeated join evaluation and a double publishing of videos removed; the comparison names
  only the archive it reads (v8). Left: the two copies of the loose-part finder (infantry and units) are to be
  merged when the infantryman moves onto the units' toolkit.
