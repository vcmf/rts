# 0038 Figures: code in tools, sources out of git, a generated registry

## Context

The animation pipeline (a line infantryman, a gun and its crew, a cavalryman on his horse) lived in an
untracked folder of one checkout, each script using its own folder as source, work area and output. Nothing
was versioned or reviewed, and nothing in the repository said which figures and clips exist. The owner
agreed on 2026-10-17 to move it in as it is, with a generated registry, before more animation work (the
figure animation proposal, `docs/proposals/figure-animation.md`, open question 3).

## Decision

We will keep figures in four places:
- **Code** in `tools/unitpipe/` (versioned, reviewed), one paths module naming every other place.
- **Sources** (Tripo exports) out of git, in assets/tripo/<army>/<model>/, listed by SHA-256 in
  `tools/unitpipe/sources.json` and checked by `tools/unitpipe/sources.py --check`.
- **Work files and published figures** (Blender files, frames, GLBs, clip tables, videos) in a git-ignored
  output/ folder.
- **The registry** `data/figures/index.json`, generated by `tools/unitpipe/registry.py` from the published
  clip tables and committed, the one place the game and the docs read which figures and clips exist.

Figure ids name the army and the kind (`fr-line-infantry`, `fr-foot-artillery`, `fr-cuirassier`).

## Consequences

- Good: the pipeline is reviewed and cannot be lost; a fresh checkout with the sources rebuilds every
  figure; the registry cannot drift from what was published, and a unit test checks its consistency.
- Bad: the sources and the archived versions the infantry check compares against live outside git and must
  be restored by hand; the registry is regenerated locally (it needs Blender), not in CI; game data files
  for figures are a later step.

## Alternatives considered

- Sources in Git LFS: needs LFS for every clone; their licence was not settled when this was written.
- A hand-written registry: drifts from what was published.
- The GLBs committed: megabytes per figure that the game does not load (it loads baked data).

See: `docs/systems/figure-pipeline.md`, `docs/plans/active/figure-pipeline.md`.
